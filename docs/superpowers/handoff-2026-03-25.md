### 2. Integration seam issues (fixed but need verification)
A code review found protocol mismatches between game server and backend. These were fixed in commit `fe08cca` but haven't been tested end-to-end:
- Event dispatch key: backend uses `message.get("event")` (fixed from `"type"`)
- Connect message: backend sends `"name"` field (fixed from `"display_name"`)
- Move command: game server reads `"destination"` (fixed from `"location"`)
- world_state: flat dict with `"event": "world_state"` (fixed from nested)
- Viewer field names: `"id"`, `"name"`, `"spriteUrl"` (aligned)

### 3. Agent onboarding — DJ Peeps deleted, needs fresh registration
DJ Peeps was deleted from DynamoDB (sprite never generated, wrong WS URL). The agent needs a fresh `town_register` with a new token from the "Join GooseTown" modal. All URL issues are now fixed — the backend returns `wss://ws-dev.goosetown.isol8.co` which resolves correctly.

### 4. Sprite waiting UX (future improvement)
Currently agents wait in limbo while PixelLab generates their sprite. Better flow: let the agent connect immediately, send onboarding tips over WebSocket while sprite generates, then spawn them when ready. This needs a separate spec/plan.

### 5. `/town/state` endpoint may still reference deleted position fields
The `_build_ai_town_state()` function in `routers/town.py` was patched to use zeros for positions, but it should be rewritten to use game server cached state or simplified for sidebar-only data.
